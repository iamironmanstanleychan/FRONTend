2. 圖片檔與網頁的關係

  • img 指向另一個檔案
  • src 由 HTML 所在位置起算
  • 圖片跟網站一起保存

店舖櫥窗可以換照片，窗框本身不會變成照片。HTML 的 img 也是引用另一個圖片檔案，輸入檔名並不等於已經取得圖片。首頁與 images 資料夾放在同一層時，images/milk-tea.svg 的意思就是先進 images，再找該檔案。外層資料夾改名，這個內部關係仍然相同。

操作：把學員課堂檔案內的 images 及 media 複製到自己的網站根資料夾；如已有同名素材，先保存原副本再比較。核對 milk-tea.svg 與 beef-noodles.svg 確實在 images 內。

3. img 的屬性

  • src：檔案位置
  • alt：此圖的意思
  • width、height：尺寸及比例

我們逐項看這個標籤。src 負責找圖；alt 負責交代這張圖在目前內容的意思。width 和 height 的數值以 CSS 像素表示尺寸，也可協助瀏覽器預留比例。這兩張教學圖原尺寸都是 480 乘 320，所以先沿用這個比例。img 是空元素，HTML 不寫結束標籤。不要把圖片拉成與原圖不同的比例。

<img src="images/milk-tea.svg"
  alt="港式奶茶的教學示意圖"
  width="480" height="320">

操作：在 index.html 現有內容之後、body 結束前輸入這段。儲存並重新載入，對照實際檔名。

4. 替代文字的內容

  • 交代圖片用途
  • 純裝飾圖片可用空 alt
  • 食品及價錢保留文字

試想圖片暫時載入不到，訪客仍要知道這裏介紹的是奶茶。alt 寫有用的內容，比寫「圖片一」清楚。如果圖片純粹裝飾，而且附近文字已完整提供資訊，可以用空字串 alt=""，讓輔助工具略過。食品的名稱和價錢應另外用文字寫出來；alt 也不應塞進一大段餐牌。

操作：在自己另存的練習副本暫把 src 改為 images/missing.svg，觀察圖片失效時附近文字是否仍清楚。修正後重新載入。

5. figure 與 figcaption

  • figure：一組獨立內容
  • figcaption：可見說明
  • alt 與說明各有用途

書本的插圖常常連着一行圖說。figure 把圖片與圖說組成一個整體，figcaption 則放所有人都看得到的說明。圖說可以交代食品、價錢及這是示意圖。alt 仍然描述圖片本身的重要意思，兩者不用逐字重複。figure 也可以包程式片段或圖表，並非每張圖片都一定要用。

<figure>
  <img src="images/milk-tea.svg" alt="港式奶茶示意圖"
    width="480" height="320">
  <figcaption>港式奶茶，HK$22。教學示意圖。</figcaption>
</figure>

操作：把剛才的 img 包進 figure，加入 figcaption；只改該區塊，保留原有首頁內容。

6. 圖片格式與來源

  • JPEG：常見照片
  • PNG：可保留透明區域
  • SVG：向量圖形

照片通常可以用 JPEG；需要透明區域時常見 PNG；本課的 SVG 是向量示意圖。選擇格式要看內容和用途，改副檔名不會把檔案真正轉換格式。這裏先使用已準備好的原創素材，並保留來源說明。自己選圖時，要確認有使用權及保存來源，不能假設搜尋得到便可任意使用。

操作：開啟 images/SOURCE.md，閱讀來源。比較兩張圖的內容，再在首頁加入乾炒牛河的 figure。

8. 聲音的播放控制

  • audio controls
  • 使用者決定播放時間
  • 提供聲音內容說明

手機語音訊息要按播放才聽到，網頁也可以把選擇留給訪客。audio 加 controls 後，瀏覽器提供播放和音量等控制，外觀會隨瀏覽器不同。本例只是短提示音，文字會說明它的用途；若改用有說話內容的錄音，便要提供相應逐字文字。預設不安排自動播放。

<audio controls src="media/chime.wav"></audio>
<p>短提示音示範，由訪客自行播放。</p>
<p><a href="media/chime.wav">開啟提示音</a></p>

操作：在首頁加入音訊區，輸入以下內容並保存。按播放，核對檔案位置及裝置音量。

9. 影片與來源格式

  • video controls
  • source 指定候選檔案
  • type 協助辨識格式

video 是影片播放器，source 讓同一播放器列出可用來源。瀏覽器會按自己的支援選擇，不是同時把所有來源播放。副檔名、編碼及實際檔案都會影響能否播放，因此不能只看到 .webm 就保證任何裝置都成功。本包提供一段約三秒的文字標牌影片，先在本機練習。

<video controls width="480">
  <source src="media/lesson.webm" type="video/webm">
</video>

操作：在音訊之後加入影片。確認 media/lesson.webm 已經存在，由 Live Server 開啟首頁。

10. poster 與載入提示

  • poster：播放前的封面
  • preload：載入偏好
  • autoplay 受瀏覽器限制

影片封面像影碟封套，只是播放前的提示，不會變成影片內容。poster 可以引用現有圖片。preload 是給瀏覽器的偏好，不能保證一定預先下載；autoplay 也可能被瀏覽器攔下。本節以 controls 及手動播放為主。若要嘗試 poster，可用已有奶茶圖，再決定這張圖是否適合影片意思。

操作：在獨立練習副本的 video 加 poster="images/milk-tea.svg"，比較播放前後畫面，再保留符合內容的版本。

11. 字幕檔與 track

  • WebVTT 時間區間
  • track 指向字幕檔
  • 語言及顯示名稱

字幕是另一個文字檔案，時間區間決定何時顯示內容。track 的 src 指向它，srclang 交代字幕語言，label 是播放器選單看到的名稱。這段影片沒有真人語音，我們用 captions 練習載入文字軌。較長影片仍要讓字幕與聲音及重要畫面資訊配合；有字幕檔不等於內容已完整。

<track src="media/lesson.vtt" kind="captions"
  srclang="zh-Hant" label="中文字幕" default>

操作：在 video 的 source 後、結束標籤前加入 track。由 HTTP 網址播放並在字幕選單選擇中文。

12. WebVTT 的時間

  • 檔首 WEBVTT
  • 開始時間 --> 結束時間
  • 字幕文字另起一行

打開字幕檔會看到 WEBVTT，接着是空行、時間，再到字幕文字。箭嘴左右都是時間，不是檔案路徑。本片只有三秒左右，字幕的結束時間也要配合片長。改 label 只會改選單名稱；要改真正的字幕文字，必須修改 VTT。儲存後重新載入，必要時重新選取字幕。

WEBVTT

00:00:00.000 --> 00:00:03.000
這是課堂教學網站，沒有真實接單。

操作：用 VS Code 開啟 media/lesson.vtt，對照時間與內容。保留 WEBVTT 及空行。

13. 播放器旁的普通連結

  • 連結放在播放器外
  • 另行開啟媒體
  • 文字持續可讀

播放器裏的後備文字主要為不支援該元素的情況而設，並不保證任何播放錯誤都會把它顯示出來。因此，把普通連結和內容說明放在播放器外面，訪客便一直看得到。本節保留影片的用途文字和開啟檔案連結。遇到格式或網絡問題，使用者還有清楚的下一步。

操作：在 video 後加用途說明及 media/lesson.webm 連結，完成第 2 題。不要把連結只放在 video 標籤裏面。

  • 觀察文字軌名稱

15. iframe 是頁內另一個網頁

  • src：另一份 HTML
  • title：框架用途
  • 原頁與嵌入頁各自存在

可以把 iframe 想成牆上的電視窗口：主頁保留自己的內容，窗口顯示另一份網頁。那份網頁仍有自己的 HTML、標題及內容。本節建立 location-preview.html，只放虛構位置說明，再把它嵌入首頁。iframe 不代表內容天然安全；來源、權限及網站政策仍然要考慮。

操作：在自己網站根建立 location-preview.html，使用筆記的完整基本骨架，寫 h1「位置示意」及一段虛構地址說明。

16. 嵌入本地位置說明

  • 相對 src
  • 可理解的 title
  • 明確尺寸

首頁與位置說明頁在同一層，所以 src 直接寫檔名。title 讓使用輔助工具的人知道這個框架用來做甚麼，不能只寫 iframe 一。width 和 height 的 HTML 屬性填數字，這裏先用固定尺寸；百分比及響應式外觀會在 CSS 章處理。

<iframe src="location-preview.html"
  title="陳記位置示意" width="480" height="240"
  sandbox></iframe>

操作：在首頁加入 iframe。確認獨立開 location-preview.html 與框架內看到相同位置內容。

17. sandbox 的限制

  • 空 sandbox 套用限制
  • 只開需要的權限
  • 來源可信仍要判斷

本例的子頁只有文字，不需要腳本、表單或彈出視窗，所以使用空 sandbox 即可。加入權限字樣會放寬部分限制，不應為了消除問題便全部加上。尤其不要把同來源的 allow-scripts 和 allow-same-origin 當成一般解法一起照抄。這裏理解限制的用途便足夠，外部服務的設定要按官方嵌入指示逐項判斷。

操作：保留本地示範的空 sandbox。若改動後子頁空白，先獨立開啟子頁，核對路徑與 HTML。

18. 嵌入頁的普通入口

  • iframe 外保留連結
  • 清楚的連結文字
  • 相同本地檔案

訪客可能想把位置說明獨立打開，也可能遇到嵌入限制。普通連結提供直接入口。連結放在 iframe 後面，href 與框架 src 指向同一個本地頁。這也接續上章連結的概念：文字先說明目的地，使用者才知道按下去會到哪裏。

<p><a href="location-preview.html">
  獨立開啟位置示意
</a></p>

操作：完成練習第 3 題，在 iframe 後加入普通連結，再按連結核對地址欄與頁面標題。

19. 外部嵌入服務

  • 使用服務提供的嵌入網址
  • 內容可能限制嵌入
  • 保留普通連結

YouTube 或地圖服務通常提供專用的嵌入網址，普通觀看網址未必可以直接放入 iframe。即使 HTML 正確，網絡、版權、登入或網站政策也可能阻止顯示。導師可以比較服務的分享選單，但課堂操作仍以已保存的本地位置頁完成。外部載入失敗時，不把它誤判為所有 HTML 都寫錯。

20. script 的角色

  • HTML 表達內容結構
  • JavaScript 增加行為
  • 腳本可由另一檔案載入

自動門的感應系統收到訊號才執行動作，JavaScript 也可以讓頁面回應操作。HTML 先描述標題、連結與按鈕；腳本再決定按下後發生甚麼。script 是引入程式的元素。本節只辨認檔案關係，完整變數、事件和計算留待 JavaScript 章。學員主站不需要先抄一段還未理解的計算程式。

<script src="script-demo.js" defer></script>

21. noscript 的適用情況

  • 腳本停用時的內容
  • 重要說明本來就要可讀
  • 執行錯誤要另行處理

餐牌可以在電子系統停用時改看紙本，noscript 也提供腳本停用或不支援時的替代內容。可是腳本下載失敗、語法錯誤或計算錯誤，不會一律觸發 noscript。因此重要的地址、價錢及用途，應本來就存在 HTML 中。後續學程式時會再處理執行錯誤。
